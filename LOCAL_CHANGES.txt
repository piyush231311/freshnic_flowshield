2. BACKEND & HYDRODYNAMIC ENGINE CHANGES
--------------------------------------------------------------------------------
A. Disruption Spatial Metadata & Fast API Endpoint (server.py)
   - Created `get_disruptions_metadata(grid_size, drain_failure, blockage, city)`:
     * Calculates spatial overlap and primary ward attribution using `city["region_map"]` dynamically.
     * Blockage primary wards: Every ward containing blocked channel cells (Ward 10 / W-11 at grid 40 & 80).
     * Drain failure primary wards: Wards with >= 25% overlap (Wards 9, 10, 13, 14; partial overlap Wards 8, 11, 12, 15).
   - Added fast GET `/api/disruptions?grid_size=40&drain_failure=true&blockage=true` endpoint (returns metadata in <5ms without running simulation).
   - Added `disruptions` array directly to the `/api/simulate` response payload.

B. Additive Impact Object & Same-Storm Baseline (server.py)
   - When disruptions are enabled (`drain_failure` or `blockage`), the server automatically runs the identical storm (same rainfall intensity, duration, initial water depth, and grid resolution) with disruptions disabled.
   - Cached baseline runs in `_BASELINE_SIM_CACHE` by `(intensity, duration, initial_water, grid)`.
   - Computes additive `impact` object isolating disruption consequences:
     * `totals`: `delta_peak_affected`, `delta_peak_affected_pct`, `delta_critical_cells`, `delta_critical_wards`, `delta_peak_depth_m`, `delta_first_critical_min`.
     * `per_ward`: Array of 16 ward comparison objects with `id`, `name`, `code`, `worst_status_with`, `worst_status_without`, `delta_max_depth`, `first_critical_min_with`, `first_critical_min_without`, and `worsened` boolean (`s_with > s_without` or `delta_d > 0.05m`).
     * `baseline_region_status`: [T, 16] status series for the unperturbed baseline storm.
     * `baseline_affected_pop`: [T] affected population series for the unperturbed baseline storm.
   - When no disruptions are active, `impact` is null.

C. Stress Matrix Scenarios Redefinition (server.py)
   - Redefined the 5 stress testing scenarios so comparisons share a single storm framework (Grid 40, 4 h duration):
     1. Normal Rainfall (`normal_baseline`): 15 mm/hr, 4 h, no events (60 mm total) -> Baseline Reference ("Ref", 0 people affected).
     2. Heavy Rainfall (`heavy_base`): 50 mm/hr, 4 h, no events (200 mm total) -> Baseline Reference for Heavy ("Ref", 4,632 people affected).
     3. Heavy + Drain Failure (`heavy_drain_failure`): 50 mm/hr, 4 h, 60% drain loss at T+60m -> +998 people (+22%), +0.18m peak depth.
     4. Heavy + Canal Blockage (`heavy_blockage`): 50 mm/hr, 4 h, culvert blockage at T+30m -> +2,319 people (+50%), +0.00m peak depth.
     5. Extreme Compound (`extreme_compound`): 75 mm/hr, 4 h, both events (300 mm total) -> 104,638 people affected (+63,456 / +154% over 75 mm/hr baseline).
   - Delta depth and delta pop strictly compare against the same storm without events; baseline rows show "Ref".
   - Dynamically generated narrative descriptions computed from simulated metrics (critical wards, first critical minute, residents affected).
   - Eliminated all "backwater" wording; blockages explicitly documented as acting by ponding in the blocked cells.

D. Default Grid Resolution (server.py)
   - Set default `grid_size = 40` across `SimulationRequest` and GET `/api/early-warning`.
   - Synchronized server default with UI and stress testing matrix.

E. Antecedent Standing Water & Low-Ground Inundation (engine/run.py & engine/ensemble.py)
   - `initial_water_m` is applied strictly to low ground (cells at or below the 20th elevation percentile `z <= z_20` plus cells in `channel_mask`).
   - High ground cells remain dry (`h = 0.0 m`) at t=0.
   - Applying `initial_water_m = 0.5 m` ($h_{crit}$) results in 27.38% (grid 40) / 24.38% (grid 80) affected population at t=0, clearly below 100%.

F. Per-Ward Telemetry (engine/run.py)
   - Added `crit_pct` (fraction of cells with $h \ge 0.5\text{ m}$) and `max_depth` to `region_data`.

   - Synchronized simulation run truth: `simData.disruptions` becomes active truth after run.

B. Disruption Status Chips & Accessible Toggles (frontend/src/components/TacticalPlaybackBar.jsx)
   - Converted disruption toggles into semantic `<button>` elements with `aria-pressed` and visible `ON`/`OFF` text.
   - Text status chips next to toggles displaying multi-state status:
     * Canal: "Canal: open" / "Canal blockage ARMED: press RUN SIMULATION" / "Canal blockage scheduled at T+30 min" / "Canal BLOCKED since T+30 min".
     * Drains: "Drains: normal" / "Drain failure ARMED: press RUN SIMULATION" / "60% capacity lost in W-10, W-11, W-14, W-15" (active) / "60% capacity loss scheduled at T+60 min".
   - Accessibility: Added `aria-live="polite"` region announcing disruption start events when playback crosses start timestamps (T+30m, T+60m).

C. Disruption Spatial Overlays & Schematic Node Visuals (frontend/src/components/TacticalNodeNetwork.jsx)
   - Armed Disruption Preview: Primary wards receive a dashed outline and icon badge prior to simulation run.
   - Active Canal Blockage (t >= 30 min):
     * Edges connecting to/from primary wards turn red (`#f87171`), dotted (`strokeDasharray="6 12"`), animate 3x slower (minimum 6s), and render an alert icon at the midpoint.
     * Non-disrupted arrows remain cyan.
   - Active Drain Failure (t >= 60 min):
     * Primary wards receive a badge ("drains -60%") and red dotted outline.
     * Partial overlap wards receive a lighter badge.
     * Arrows are NOT recolored for drain failure (drainage sink loss, not lateral conveyance reduction).
   - Worsened Ward Markers:
     * Wards with `worsened: true` display a `▲ WORSENED` badge and accessible tooltip note.
   - Clean Baseline Mode:
     * When "Show without disruptions" is enabled, schematic switches to `baseline_region_status` and hides disruption overlays.
   - Accessible Node Network:
     * Ward nodes: `tabIndex={0}`, `role="button"`, descriptive `aria-label` (e.g., "Ward 11, Critical, canal blocked, drains impaired, worsened by disruption").
     * Visible high-contrast focus rings.
     * Flow path SVG `<title>` attributes (e.g., "Flow between Ward 10 and Ward 11: restricted by canal blockage").
     * Respects `prefers-reduced-motion: reduce` by replacing SMIL animations with static dotted strokes.
     * Flow legend: Solid cyan (normal flow), red dotted (restricted flow), badge (drain failure).
   - Tooltips:
     * Displays Peak Depth and % Critical Cells with rule: "*Critical = >5% of cells >= 0.5m".
     * Hides "Inflow Source" row when volume is 0 or source is self-contained.
